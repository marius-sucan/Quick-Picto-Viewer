# QPV bug audit — 2026-08-27

Whole-codebase audit run 2026-08-27 on master @46a2605 (AHK sources + `QPV DLL source code/`).
Reported to the user; **not fixed at the time of writing**. Line numbers are as of 46a2605.
Everything below was traced in the code; nothing could be executed on this machine, so the
reproduction steps describe what the code does, not what was observed on screen.

## Confirmed, most severe first

1. **The "QPV audio volume" slider in Preferences does nothing until QPV is restarted** —
   `PanelPreferencesWindow()` :57982 builds it as
   `GuiAddSlider("mediaSNDvolume", 1,100, 50, "QPV audio volume", "dummy", ...)`; the slider
   machinery writes the global directly (`GuiSlidersResponder()` :104619 `%givenVar% := ...`)
   and `BtnSavePreferencesClose()` :58470 stores it (`INIaction(1, "mediaSNDvolume", ...)`
   :58503) — but **nothing calls `SetVolume()`**. The only two call sites are
   `readMainSettingsApp()` :38972, inside its `If (act=0)` read-only branch (so: application
   start), and `ChangeSoundVolume()` :12117 (its `SetVolume` call at :12149), reached from
   `MenuSetVolumeUp/Down()` :70199 /
   Shift+. / Shift+, . `SetVolume()` (`lib/shell-stuff.ahk:1230`) is the only thing that ever
   issues `waveOutSetVolume`, so the level actually in force stays whatever it was at start-up.
   Repro: play an audio annotation or a slideshow song so you can hear it, open Preferences,
   drag "QPV audio volume" from 80 % down to 5 %, press Save — the audio keeps playing at the
   old level, and it stays there for the rest of the session. Restart QPV and it is at 5 %.
   Or press Shift+. once after saving: the volume jumps to 10 % and *that* takes effect, which
   makes the slider look like it lags one keypress behind.
   Fix: call `SetVolume(mediaSNDvolume)` from `BtnSavePreferencesClose()` (or give the slider a
   real `func2exec` instead of `"dummy"`).

2. **The folders tree's `7` / `Shift+7` shortcuts do nothing while the tree window has the
   keyboard focus** — which is where its own menu advertises them, and where the user is
   standing right after picking the destination folder. `folderTreeContextMenu()` :31637-31638
   adds `kMenu("PVfdTree", "Add", "Cop&y selected file(s) into...`t7", "FolderTreeMenuCopyFiles")`
   and `"&Move selected file(s) into...`tShift+7"` → `FolderTreeMenuMoveFiles`, and
   `resources/help-keyboard-shortcuts.txt:259-260` documents both under the context
   "Folder tree". The key is only routed from the **main** window: `processDefaultKbdCombos()`
   :2055-2063 maps `isInRange(givenKey, 1, 7)` to `triggerQuickFileAction()` :46457, whose
   `thisVar=7` branch :46484 reads the tree's current selection — but that dispatcher is
   reached only from the `thisWin=PVhwnd` arm of `KeyboardResponder()` :921. The tree GUI is
   created `+Owner%PVhwnd%` (:30631), so `identifyParentWind()` :27440 returns 1 for it and
   its keys arrive as `thisWin="parentu"` (:757), a branch that handles only `^x` / `^c` for
   `Az=hfdTreeWinGui` (:869-872). `FolderTreeResponder()` :30827 has no VK 55 branch either —
   it handles VK 32/46/93/112-116/118-120/123/186 only, and every other accelerator that menu
   advertises does map to one of those.
   Repro: List > Folders tree view (F4) — the tree window takes the focus. Select files in the
   list, click the destination folder in the tree, press `7` — nothing happens. Click back on
   the main window (without touching the tree selection) and press `7` — the files are copied.
   The tree's own right-click menu works from either place.
   Fix: add VK 55 (with a Shift test) to `FolderTreeResponder()`, or let the `"parentu"` branch
   forward `7`/`+7` for `Az=hfdTreeWinGui` the way it forwards `^x`/`^c`.

3. **Seen images statistics, "Days" chart: "N days lack data." can never appear, and the
   calendar walk that used to feed it is now dead code** — `PlotSeenDaysStatsNow()` :28869.
   The 08-26 audit reported that `If (nYear . thisM>20200401)` (a 6-digit value compared
   against an 8-digit one) never fired; the line was removed instead of corrected, so the
   loop at :28898-28921 now walks the whole period one day at a time, computes `dateu`,
   and **uses nothing it produced** — `nYear`, `nMon`, `nDay` and `dateu` are never read
   after the `Break`. The only remaining writer is :28949
   `dataSkipped[oIndexu] := valu ? 0 : 1`, keyed on the rows that are *in* the list view;
   those rows come from a grouped query, so every one of them carries at least one image and
   the value is always 0. `countSkipped` :28968 is therefore always 0 and `lacking` :28974 is
   always blank. The "Months" chart still works, because :28758 seeds `dataSkipped[dateu] := 1`
   for every month in the range before the list-view pass clears the ones that have data.
   Repro: seen-images statistics panel → Charts → "Months" reports "N months lack data.";
   "Days", over the same recorded period with gaps in it, never does. The dead walk also costs
   one pass per day of the period each time the button is pressed (it stops at the last date
   or at its own 2.5-second cap, whichever comes first).
   Fix: seed `dataSkipped[dateu] := 1` inside that loop the way the Months plot does — the
   guard, if one is wanted at all, has to compare like with like (`nYear thisM thisD>20200401`).

4. **The slideshow-duration panel prints a doubled "~"** — `EstimateSlideShowLength()` :58912
   already prefixes its result with the approximation marker (`:58915` computes
   `approxMarker`, `:58928` returns `approxMarker SecToHHMMSS(...)`). The 08-24 audit reported
   that `DefineSlidesTotalTimeBTNaction()` displayed no "~" at all; the fix added a second
   `approxMarker` there (:58907) and prepends it again at :58909, so the duration line comes
   out as `Estimated slideshow duration: ~~00:00:33`. The rate on the same line is correct
   (`DefineSlidesRate()` :58846 does not prefix). The panel's initial text, built at :58760
   before any control is touched, is also correct — the doubling appears the moment anything
   in the panel changes.
   Repro: Slides > "Define total slideshow time" (the panel shows a single `~`), then pick
   "30 FPS" in the Speed drop-down (or type anything in Hours/Minutes/Seconds) — the
   "Estimated slideshow duration" line now starts with `~~`. The marker only shows at all when
   `slideShowDelay < drawModeCzeit + 50`, i.e. at speeds faster than the measured image load
   time, so use one of the FPS presets.

## Minor / cosmetic

- `realtimePasteInPlaceAlphaMasker()` :15750 —
  `thisu := ((offX.sw != offX.dh || offX.sh != offX.dh) && offX.invertArea=0) ? 1 : 0`.
  The first comparison reads `offX.dh` where the pair it belongs to wants `offX.dw`; as
  written, `thisu` is 1 whenever the selection's width differs from its height. The guard it
  feeds (:15751) then calls `getRectFromBitmap(alphaMaskGray, offX, 1)` for every non-square
  selection, including the ones that need no crop at all. With `dx/dy/dw/dh` equal to
  `sx/sy/sw/sh` that call clones the whole mask and, if `selObj.nw`/`nh` differ from the mask's
  own size, rescales it — so at best a wasted clone per preview frame, at worst a resampled
  alpha mask. The complementary case (`sw != dw` while `sw = dh = sh`) is masked by the other
  terms of the same `If`. Not reproduced on screen; reported as a traced typo.
- `PanelSearchAndReplaceIndex()` → "Apply action on: Main seed folders list"
  (`BTNperformIndexSearchReplace()` :46299-46316) collapses every `\\` in the list to a single
  `\` at :46313. That step exists to undo the separators the routine itself adds at :46311,
  but it also eats the leading `\\` of a UNC seed folder, turning `\\NAS\photos` into
  `\NAS\photos` — and it does so even when the search string matched nothing. The same branch
  refuses to run at all on a list that holds no `:\` (:46301), so a seed list made only of
  network shares reports "WARNING: The seed folders list is empty". Conditional on UNC seed
  folders being reachable: "Paste list" filters them out (`BTNpasteDynaFoldersList()` :95878,
  `RegExMatch(fileTest, "i)^(.\:\\.)")`), so they can only enter through the folder picker in
  `addNewFolder2list()`. Worth a look before fixing.
- `PanelStructuredCopyMoveWindow()` :60308 — the header text is built as
  `%infoSelection%This panels allows users to...`, but `infoSelection` is not assigned until
  :60324, so the "Selected files: N." prefix is always blank there. The same string is shown
  correctly next to the buttons at :60333.
- `copyMoveStructuredFolders()` :3240 — `prevuDir := OutDir` (:3322) is set only inside the
  `If !FolderExist(OutDir)` branch, so for a destination sub-folder that already exists the
  `FolderExist()` probe is repeated for every file that lands in it.
