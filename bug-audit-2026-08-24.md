# QPV bug audit — 2026-08-24

Whole-codebase audit run 2026-08-24 on master @3fc3a2a (AHK sources + `QPV DLL source code/`).
Reported to the user; **not fixed at the time of writing**. Line numbers are as of 3fc3a2a.
Everything below was traced in the code; nothing could be executed on this machine, so the
reproduction steps describe what the code does, not what was observed on screen.

## Confirmed, most severe first

1. `coreExtractFramesFromImage()` / `coreExtractFramesFromTiff()` / `coreExtractFramesFromWEBP()` /
   `coreImgCombinerLoadFimFile()` — the frame index base is off by one, four ways:
   - GIF (and TIFF when FreeImage is off) :62261/:62299 — `tFrames := count-1`, then
     `Gdip_BitmapSelectActiveFrame(oBitmap, A_Index)` for 1..count-1: the FIRST frame is never
     written, N-1 files come out, the message says "Extracting N-1 frames".
   - TIFF via FreeImage/WIC :61907 — `frameu := clampInRange(A_Index, 0, tFrames-1)` over 1..count:
     page 1 is never written, `_N-1` and `_N` are both the last page.
   - WEBP :61981 — `tFrames := mainLoadedIMGdetails.Frames` (= count-1); `_0` is saved, then
     A_Index=1 is skipped and A_Index-1 loaded: frames 1..count-2 -> the LAST frame is never
     written, files are numbered `_0, _2, ...` (a 2-frame WEBP yields only `_0`).
   - Join images (GIF/TIFF output, "Join contained frames") :62920 — `Loop tFrames+1` with
     `clamp(A_Index-1, 0, count-1)`: the last page is pushed twice.
   Repro: Image > Extract frames/pages on an animated GIF with N frames -> N-1 files, first frame
   missing. Same panel on a multi-page TIFF -> first page missing, last page twice. PDF extraction
   (`A_Index-1`) and the viewer's own frame selection (:100147, 0-based clamp) are correct.

2. `PasteHDropFiles()` :25250 — `countFiles := ST_Count(Trimmer(imgsListu), "`n")`. AutoHotkey
   returns CF_HDROP as names joined by `\r\n` with no trailing newline, so ONE file copied in
   Explorer gives `countFiles=0`, the import prompt is skipped, `msgResult` is blank and the paste
   is a silent no-op (the function still returns 1, so `MenuPasteHDropFiles()` shows nothing).
   N files -> the prompt says "N-1 file entries". `addNewFile2list()` :63805 does the `+1`.
   Repro: copy a single image in Explorer, press Ctrl+V in QPV (or the toolbar Paste in list
   mode) -> nothing happens; copy two -> "You have 1 file entries...".

3. `coreBatchMultiRenameFiles()` :41361 — "Preserve original file date and time" reads
   `FileGetTime ... %file2save%` (the DESTINATION name) instead of `%file2rem%`, and does so
   BEFORE the collision handling. Without a collision the value is blank and nothing happens
   (a rename keeps the dates anyway). With a collision + Auto-rename the renamed file receives
   the COLLIDING file's modified/created dates; with Overwrite it receives the overwritten
   file's dates. `BTNrenameSoloFileAct()` reads `file2rem` correctly.
   Repro: folder with `b.jpg` (dated 2020) and a pre-existing `x (1).jpg` (dated today). Select
   b.jpg + one more, Rename multiple files, pattern `x`, tick Preserve date, collisions =
   Auto-rename, Rename -> `x (1) [1].jpg` now carries today's dates.

4. `removeFilesListSeenImages()` :35847 (also the "faves" mode behind "Remove favourited images
   from list") — with a files-list filter active the removed rows are blanked in the backup list
   through `updateMainUnfilteredList()`, but `resultedFilesList := newArrayu.Clone()` is done
   WITHOUT rebuilding `filteredMap2mainList` (`InListMultiEntriesRemover()` and
   `cleanDeadFilesList()` both rebuild it). Every later per-entry operation on the filtered list
   then writes to the wrong backup row; because the row objects are shared, the wrong file is
   hit when the filter is dropped.
   Repro: open a folder, star images 1-3, apply a filter that keeps everything, List > Remove
   favourited images, then Alt+Delete (remove index entry) on the first remaining image, then
   remove the filter -> the removed entry is back and a different image is gone from the list.

5. `moveSelectedPointsInVectorPath()` :9449 — `zx := (FlipImgV=1) ? -1 : 1`,
   `zy := (FlipImgH=1) ? -1 : 1`: the two flips are swapped. With exactly one viewport flip
   active, dragging a multi-point selection moves it mirrored on BOTH axes (both flips cancel
   out, so that case is correct). The single-point drag uses `mainWidth - mX` and is fine.
   Repro: flip the viewport horizontally, pen tool, add points, Shift+click two points, drag
   one -> the selection moves left when the mouse moves right and up when it moves down.

6. `MenuRemSelVectorPoints()` :7359 (and `MenuCollapseSelectedAnchorPoints()` :7275) — in
   symmetric Bezier mode: (a) `zb .= totalCount - b + 1` :7412/:7321 is a concatenation, so from
   the second selected key point on `zb` is e.g. "74" and a bogus row is marked while the real
   mirrored anchor is not; (b) the mirrored KEY point (`oppoIndex`) is never marked, only its
   anchors `za`/`zb`, so after the removal the mirror keeps its key point but loses its anchors
   and the point count stops being a multiple of 3 (anchors and key points shift). Click
   selection masks this because `selectGivenPointInVectorPath()` also selects the mirror;
   rectangle selection (Select mode) and Invert selection do not.
   Repro (traced, not run): Bezier path, symmetry on, Select mode, drag a rectangle over two key
   points on one side, press Delete -> garbled path. (:9529 has the same `.=` but on a fresh
   local, harmless.)

7. `coreAddUnorderedVectorPointPolyMode()` :7895 — the closing edge of a closed POLYGONAL path
   can never take a point: `PointsListArray[totalCount+1]` is never filled (the wrap writes
   slot 1 twice), so the last->first edge tests against blanks; the loop bound is also keyed on
   `FillAreaClosedPath` (the draw-shapes panel checkbox) instead of `closedLineCustomShape`.
   Repro: pen tool, polygonal path type, closed path, 3+ points, Alt+click on the middle of
   the last edge -> nothing (any other edge works; curved modes handle the closing edge).

8. `updateUIFiltersPanel()` :33080 / `processSQLsearchIndexString()` :39972 — on .SLDB lists
   the panel still says "use | for OR and the *, ? wildcards", but the SQLite branch does
   `StrReplace(*, "_")` (`*` matches exactly ONE character) and `StrReplace(|, "")`
   (`cat|dog` becomes `catdog`). Plain-text lists go through `JEE_StrRegExLiteral()` and work.
   Repro: any .SLDB list, Files list filter, string `cat|dog` -> "No files matched", list restored.
